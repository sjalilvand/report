# سکوی هوشمند آماده‌سازی داده، مدل‌سازی و گزارش‌سازی

سامانه تحت وب گزارش‌ساز و تحلیل داده‌های اکسل — پیاده‌سازی نسخه اولیه (MVP) مطابق «سند نیازمندی‌ها و طرح جامع سامانه گزارش‌ساز و تحلیل داده‌های اکسل» نسخه ۱٫۰.

> **تجربه هوشمند (جدید):** کافی است فایل اکسل را بارگذاری کنید — سامانه خودش بهترین برگه را انتخاب می‌کند، مجموعه‌داده می‌سازد و داشبورد کامل (کارت شاخص، روند دوره‌ای، تفکیک‌ها، ترکیب سهم، بینش‌های فارسی و جدول خلاصه) را **بدون هیچ کلیک اضافه** باز می‌کند؛ چند فایل هم‌فرم هم به‌طور خودکار تجمیع می‌شود و چیدمان داشبورد قابل ویرایش و ذخیره است.

> **دامنه محصول (بخش ۳۷ سند):** دریافت منعطف داده + آماده‌سازی قابل ردیابی + مدل‌سازی صحیح + گزارش‌سازی بدون کدنویسی + انتشار امن و قابل تکرار

## اجرا

### روی ویندوز با PowerShell (توصیه‌شده)

فقط یک فایل کافی است — `public/setup-and-run.ps1` را دانلود و اجرا کنید؛ Git و Node.js را در صورت نبود نصب می‌کند، پروژه را از GitHub دریافت، دیتابیس را می‌سازد و برنامه را اجرا می‌کند:

```powershell
# دانلود و اجرای یک‌مرحله‌ای
Invoke-WebRequest https://raw.githubusercontent.com/sjalilvand/report/main/public/setup-and-run.ps1 -OutFile setup-and-run.ps1
powershell -ExecutionPolicy Bypass -File .\setup-and-run.ps1
```

گزینه‌های اختیاری: `-InstallDir "D:\apps\report"` (مسیر نصب)، `-Port 3016` (پورت پیش‌فرض: ۳۰۱۵)، `-Production` (حالت تولید)، `-SkipClone`، `-NoBrowser`.

پس از نصب، سه میان‌بر در پوشه نصب و پوشه فراخوانی ساخته می‌شود: `start-report.ps1` (اجرای سریع)، `stop-report.ps1` (توقف سرور) و `update-report.ps1` (به‌روزرسانی از GitHub + نصب وابستگی‌ها + همگام‌سازی دیتابیس). برنامه روی **پورت ۳۰۱۵** اجرا می‌شود: `http://localhost:3015` — و از دستگاه‌های دیگر شبکه با `http://<IP-سرور>:3015` در دسترس است.

### عیب‌یابی ویندوز

| خطا | علت | راه حل |
|-----|-----|--------|
| `start-report.ps1 is not recognized as a name of a cmdlet...` | در PowerShell اسکریپت‌های پوشه جاری بدون پیشوند `.\` اجرا نمی‌شوند | دستور را با `.\` شروع کنید: `.\start-report.ps1` |
| `running scripts is disabled on this system` | سیاست اجرای اسکریپت | `powershell -ExecutionPolicy Bypass -File .\start-report.ps1` |
| به‌روزرسانی ناموفق با `git pull` | تغییرات محلی روی فایل‌ها | در پوشه پروژه: `git stash` سپس `git pull` (یا `setup-and-run.ps1` را دوباره با «.\» اجرا کنید) |
| `WebSocket ... /_next/hmr ... ERR_INVALID_HTTP_RESPONSE` و/یا صفحه روی «در حال بررسی نشست…» گیر می‌کند | دسترسی با IP شبکه (مثلاً `192.168.100.5:3015`) — Next.js 16 منابع dev را برای مبدأ غیر localhost مسدود می‌کند | IP سرور باید در `allowedDevOrigins` فایل `next.config.ts` باشد (پیش‌فرض شامل `192.168.100.5` است). اگر IP سرور تغییر کرد، IP جدید را به همان فهرست اضافه و سرور را دوباره اجرا کنید. پس از هر به‌روزرسانی، میان‌برها را دوباره بسازید: `Copy-Item .\public\run-report.ps1 .\start-report.ps1 -Force` و `Copy-Item .\public\stop-report.ps1 .\stop-report.ps1 -Force` |

```powershell
# اجرای درست میان‌برها (با نقطه و بک‌اسلش):
.\start-report.ps1
.\stop-report.ps1
.\update-report.ps1
```

### اجرای دستی (ویندوز/لینوکس/مک)

```bash
# پیش‌نیاز: Node.js 20+ یا Bun
npm install        # یا bun install
npx prisma db push # ایجاد پایگاه‌داده
npm run dev        # اجرای توسعه روی پورت 3015
```

سپس `http://localhost:3015` را باز کنید (از دستگاه دیگر شبکه: `http://<IP-سرور>:3015`).

## ویژگی‌های پیاده‌سازی‌شده (خلاصه)

- **دریافت فایل**: XLSX/CSV/TSV/XLSM با Drag & Drop، چندشیت، اثر انگشت محتوا و تشخیص فایل تکراری (بخش ۳.۱ و ۷.۱)
- **داشبورد هوشمند پس از بارگذاری (تجربه خودکار)**: با ایجاد هر مجموعه‌داده، برنامه مستقیماً «داشبورد هوشمند» را نمایش می‌دهد — تشخیص خودکار سنجه‌ها، ابعاد و ستون تاریخ از ساختار داده؛ کارت‌های شاخص رنگی با چیپ تغییر نسبت به دوره قبل؛ نمودار روند ماه/فصل/سال با جدول مقایسه دوره‌ای؛ تفکیک و ترکیب سهم هر گروه (نمودار میله‌ای/دونات)؛ بینش‌های خودکار به زبان فارسی (بیشترین سهم، جهت حرکت، اوج دوره‌ای، تمرکز، کیفیت داده، بازه زمانی)؛ جدول خلاصه با نوار سهم — همه با ارقام فارسی و بدون هیچ پیکربندی؛ حالت «ویرایش داشبورد» برای مخفی/جابه‌جا کردن کارت‌ها، تغییر نوع نمودار و عنوان و ذخیره چیدمان (مطابق نمونه‌های داشبورد تحلیلی کاربر)
- **شناسایی ساختار**: سطر سرستون، دامنه داده، سطرهای عنوان و جمع کل، سطر/ستون مخفی، سلول ادغام‌شده با ۴ سیاست برخورد (بخش ۳.۲ و ۷.۲)
- **ویرایش ستون‌ها**: برچسب، نوع، نقش (بُعد/سنجه/شناسه/توصیفی)، واحد، تجمیع، حساسیت — با حفظ شناسه پایدار داخلی (بخش ۸ و معیار ۳۳.۲)
- **پروفایل کیفیت**: خالی‌ها، متمایزها، کمینه/بیشینه، میانگین/میانه، پرتکرارها، توزیع نوع، کیفیت هر ستون (بخش ۹)
- **پاک‌سازی**: ۱۶ عملیات متنی و ساختاری با دفترچه مراحل تبدیل قابل ردیابی (بخش ۱۰)
- **مدل معنایی**: تفکیک ابعاد/سنجه‌ها، سطح جزئیات، آزمون یکتایی کلید، فرمول‌نویسی امن (نسبت_ایمن، اگر، گرد، درصد)، بازه‌سازی با کنترل تداخل و پوشش (بخش ۱۱ تا ۱۳ و ۱۷)
- **گزارش‌ساز**: جدول، نمودار میله‌ای/خطی/دایره‌ای، کارت شاخص، فیلتر سراسری، جمع کل از مقادیر دقیق، گزارش توصیفی قالبی، ذخیره و نسخه‌بندی (بخش ۱۹ و ۲۰ و ۲۴.۳)
- **مبلغ و واحد پول**: مبنای ریال، ۹ واحد (ریال تا همت)، نمایش خودکار واحد مناسب، نمایش منفی با پرانتز (بخش ۱۴)
- **تاریخ شمسی**: تشخیص، اعتبارسنجی، استخراج سال/ماه/فصل/نیم‌سال/روز هفته/هفته سال (بخش ۱۵)
- **خروجی**: Excel با نوع عدد مناسب و شیت شناسنامه، CSV با BOM و جداکننده — ثبت فیلترها و نسخه داده (بخش ۲۳)
- **احراز هویت و دسترسی**: ورود امن با نشست، پنج نقش سازمانی با ماتریس مجوز، دسترسی سطح سطر، ماسک ستون محرمانه، سقف ظرفیت قابل تنظیم (بخش ۲۹ و ۳۰.۱)
- **اتصال بصری جداول**: بوم گرافیکی، شش نوع اتصال، کنترل‌های الزامی پیش از اتصال و سد جلوگیری از چندبرابرشدن مبالغ (بخش ۱۶)
- **فرهنگ داده**: شاخص‌های مرکزی با تعریف مدیریتی، فرمول، منبع، مالک و نسخه؛ تأیید شاخص و بازاستفاده در گزارش‌ساز (بخش ۱۸)
- **گردش کار تأیید و مقایسه نسخه‌ها**: پیش‌نویس ← در انتظار تأیید ← تأییدشده ← منتشرشده با ثبت دلیل رد و دلیل تغییر؛ عکس‌فوری هر نسخه و مقایسه دو نسخه دلخواه با دیف رنگی ابعاد/سنجه‌ها/فیلترها/نوع نمایش (بخش ۲۶.۱)
- **جدول محوری و نمودارهای تخصصی**: سلسله‌مراتب چندسطحی با جمع جزء/کل، سهم و رتبه؛ ماتریس/نقشه حرارتی، ترکیبی، پراکندگی، هیستوگرام، جعبه‌ای، آبشاری، قیفی (بخش ۱۹.۲)
- **فیلتر وابسته و Drill**: کاسکاد خودکار از روابط جداول، Drill Down/Through، Cross Filter داشبورد (بخش ۱۹.۳)
- **به‌روزرسانی فایل (Upsert)**: سه روش به‌روزرسانی، کنترل تغییر ساختار با توقف و تأیید مدیر، نسخه‌بندی (بخش ۲۴)
- **هشدارها و اعلان‌ها**: هر شش محرک بخش ۲۶.۲ (آستانه، کیفیت، تأخیر فایل، شکست پردازش، تغییر ساختار، نبود داده دوره) + زنگ اعلان با شمارش نخوانده و جلوگیری از تکرار
- **زمان‌بندی خودکار هشدارها و کانال ایمیل**: ارزیابی دوره‌ای همه قواعد با فاصله قابل تنظیم (بدون ری‌استارت)، ارسال خلاصه اعلان‌ها با SMTP قابل پیکربندی، ایمیل آزمایشی و ماسک گذرواژه (تکمیل ۲۶.۲)
- **تقویم مناسبت‌ها**: جدول مرجع با هشت فیلد سند (نوع تقویم شمسی/قمری/میلادی، بازه هر سال، دسته، سراسری/محلی، تعطیل، منبع/نسخه، رنگ/برچسب) + ورود گروهی از اکسل/CSV و هشدار هم‌پوشانی (۱۵.۴ و ۱۵.۵)
- **خروجی PDF و PowerPoint**: PDF مناسب چاپ با فونت جاسازی‌شده وزیرمتن و صفحه‌بندی؛ PPTX با اسلاید عنوان، نمودار بومی و جدول مدیریتی (۲۳.۱)
- **ورود یکپارچه سازمانی (SSO)**: اتصال به هر سامانه هویتی OIDC استاندارد (Keycloak، Azure AD/Entra، Google و ...) با کشف خودکار نقاط انتها از Issuer، محافظت state، پیوند حساب موجود یا ساخت خودکار با نقش پیش‌فرض و محدودیت دامنه ایمیل (بخش ۲۹)
- **احراز هویت چندمرحله‌ای (MFA)**: TOTP استاندارد با QR و کلید دستی سازگار با اپلیکیشن‌های احرازکننده، ورود دوگامی با بلیت کوتاه‌عمر تک‌مصرف، الزام MFA برای نقش‌های حساس و بازنشانی توسط مدیر (بخش ۲۹)
- **اتصال API و پایگاه‌داده خارجی (۳۱)**: سرویس REST/JSON و PostgreSQL/MySQL با پرس‌وجوی فقط‌خواندنی، تشخیص خودکار ستون‌ها، همگام‌سازی دستی یا زمان‌بندی‌شده به مجموعه‌داده با نسخه‌بندی، ماسک مقادیر محرمانه پیکربندی و پیام خطای فارسی عملیاتی
- **صف پردازش خروجی حجیم (۳۰.۲)**: تولید غیرهم‌زمان Excel/CSV/PDF/PowerPoint با نوار پیشرفت، بازیابی پردازش شکست‌خورده و یتیم پس از ری‌استارت، اجرای مجدد امن (خودکار و دستی)، ثبت مدت و علت شکست، انقضای خودکار لینک دانلود و اعلان شکست
- **مانیتورینگ سلامت سرویس**: نقطه انتهای عمومی health با وضعیت پایگاه‌داده، زمان‌بند و صف — بخش ۳۰.۲
- **تحلیل‌های پیشرفته (۲۱.۲ و ۲۱.۳)**: روند و پیش‌بینی سری زمانی (رگرسیون خطی + بازه عدم قطعیت ۹۵٪ + R²/MAE/MAPE)، گروه‌های زمانی Cohort و ماتریس حفظ مخاطبان، بخش‌بندی RFM با امتیاز پنج‌ک و نه بخش استاندارد، سناریوسازی What-if، همبستگی پیرسون با حذف جفتی و تشخیص ناهنجاری میانه/MAD — همه با ذکر روش، تعداد نمونه، داده حذف‌شده و هشدارهای صحت تحلیل
- **کارت مقایسه‌ای و نقشه جغرافیایی (تکمیل ۱۹.۲)**: کارت مقایسه‌ای دو گروه یا مقدار در برابر هدف با اختلاف مطلق/درصدی و نوار تحقق هدف؛ نقشه حبابی ایران با جدول مرجع محلی استان‌ها (۳۱ استان + نام‌های جایگزین و شهرهای بزرگ)، تشخیص خودکار ستون مکانی، گزارش شفاف مقادیر تطبیق‌نیافته و خروجی API مستقل برای آزمون
- **قابلیت‌های هوشمند و هوش مصنوعی (۲۵)**: موتور پیشنهاد محلی بدون سرویس بیرونی (نوع ستون، کلید یکتا، روابط، قواعد پاک‌سازی، نمودار مناسب، شاخص قابل محاسبه، الگوها و نقاط غیرعادی)؛ پرسش به زبان طبیعی از داده با تفسیر محلی یا مدل زبانی و اجرای همیشه با موتور دقیق محاسبات؛ پیش‌نویس گزارش توصیفی با برچسب الزامی «تأیید انسانی»؛ توضیح فرمول و خطا با قواعد محلی؛ تب «دستیار هوشمند» و دکمه «پیشنهاد هوشمند» در گزارش‌ساز؛ سیاست‌های مدیریتی (فعال‌سازی دستیار، مجوز اشتراک داده با سرویس بیرونی و سقف ردیف) در تنظیمات؛ اعلام شفاف ناتوانی، ماسک ستون محرمانه و محافظت در برابر تزریق دستور مطابق الزامات کنترلی بخش ۲۵
- **تکمیل کامل اجزای گزارش (۱۹.۲)**: جدول کیفیت داده با خلاصه سطح مجموعه‌داده (رکوردهای بررسی‌شده، سطرهای تکراری، ستون‌های دارای مشکل، بازه زمانی) و جدول ستون‌به‌ستون (خالی، درصد خالی، متمایز، کمینه/بیشینه، میانگین/میانه، خارج از الگو، وضعیت سالم/ناقص/ناسازگار) با دیالوگ جزئیات (پرتکرارها، توزیع نوع، طول متن) — بر پایه پروفایل بخش ۹ با رعایت قواعد سطری و ماسک ستون محرمانه؛ متن، تصویر، لوگو و توضیح به‌عنوان اجزای سرصفحه گزارش با ذخیره در پیکربندی؛ بخش فرمول و شناسنامه شاخص با فرمول به زبان انسانی (سنجه، تجمیع، تفکیک، واحد نمایش، فیلترها) و شناسنامه مجموعه‌داده
- **توابع آماری پیشرفته (۱۳.۱ و ۱۳.۲)**: نما، دامنه تغییرات، واریانس و انحراف معیار (جامع/نمونه)، چارک اول و سوم، صدک با p قابل تنظیم، فاصله بین چارکی و ضریب تغییرات به‌عنوان انواع تجمیع سنجه؛ میانگین وزنی واقعی با ستون وزن (Σx·w/Σw)؛ محاسبات پنجره‌ای روی نتیجه تجمیع‌شده (مجموع تجمعی و میانگین متحرک با پنجره قابل تنظیم)؛ کنترل مدیر در تنظیمات سامانه (روش صدک: درون‌یابی خطی R-7 یا نزدیک‌ترین رتبه، نوع انحراف معیار، رفتار داده‌های خالی: کنار گذاشتن یا صفر) — تبدیل واحد مبلغ پیش از محاسبه واریانس برای صحت مقیاس
- **تبدیل‌های ساختاری Unpivot و Pivot (۱۰.۲)**: «تبدیل ستون‌ها به سطر» با ستون‌های ثابت قابل انتخاب و نام‌گذاری ستون شاخص/مقدار (نرمال‌سازی خودکار مبلغ‌های ارزی به مبنای ریال برای حفظ جمع) و «تبدیل سطرها به ستون» با کلید گروه‌بندی، تجمیع (جمع/میانگین/تعداد/کمینه/بیشینه/نخستین)، مقدار پرکننده و سقف ستون خروجی با هشدار — هر دو با ثبت در دفترچه مراحل تبدیل (۱۰.۳) و رابط کاربری چندستونی در تب پاک‌سازی
- **موتور تحلیل متوسط DuckDB و فایل آماده‌شده Parquet (۲۷.۲)**: ساخت فایل Parquet ستونی از نسخه جاری هر مجموعه‌داده (CSV تایپ‌شده → جدول DuckDB → COPY با فشرده‌سازی) با ثبت نسخه/سطر/ستون/اندازه و هشدار قدیمی‌بودن نسخه؛ کنسول SQL فقط‌خواندنی روی نمای «ds» با موتور تحلیلی DuckDB برای تحلیل متوسط (سقف ۲٬۰۰۰ ردیف، تک‌دستوری، فهرست سیاه کلیدواژه‌های DDL/DML و دسترسی فایل)؛ ثبت هر پرس‌وجو در رویدادها و محدودیت کنسول به مدیر سامانه/مدیر داده (بدون ماسک — بخش ۲۹)؛ انتخاب موتور (داخلی یا DuckDB) در تنظیمات مدیر و تب «موتور تحلیلی»؛ در نبود بسته، سامانه با موتور داخلی به کار ادامه می‌دهد (گزینه فناوری، نه الزام قطعی)
- **ورود یکپارچه سازمانی SAML 2.0 (۲۹)**: اتصال به هر IdP استاندارد (ADFS، Azure AD/Entra، Okta، Keycloak، Shibboleth و ...) در کنار OIDC موجود؛ شروع ورود با Redirect Binding و AuthnRequest استاندارد، اعتبارسنجی امضای XML پاسخ با گواهی X.509 سامانه هویتی (پاسخ بی‌امضا/دستکاری‌شده رد می‌شود)، SP Metadata برای ثبت در IdP، استخراج هویت از ویژگی‌های رایج (mail/emailaddress/displayName و ...) و همان سیاست‌های SSO (پیوند حساب موجود یا ساخت خودکار با نقش پیش‌فرض و محدودیت دامنه ایمیل)؛ پیکربندی از تنظیمات مدیر (Entry Point، گواهی چندسطری، EntityID) و دکمه ورود در صفحه ورود

## وضعیت پیاده‌سازی و نقشه راه

مشخصات کامل در [`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md) — اتصال بصری جداول (۱۶)، فرهنگ داده (۱۸)، تقویم مناسبت‌ها (۱۵.۴)، گردش کار تأیید و مقایسه نسخه‌ها (۲۶.۱)، احراز هویت و کنترل دسترسی با SSO/OIDC و SAML و MFA (۲۹)، ظرفیت (۳۰.۱)، جدول محوری (۱۹.۲)، نمودارهای تخصصی (۱۹.۲)، فیلتر وابسته (۱۹.۳)، Upsert (۲۴)، تحلیل‌های پیشرفته (۲۱.۲)، هشدارها و اعلان‌ها با زمان‌بندی خودکار و کانال ایمیلی (۲۶.۲)، خروجی PDF/PowerPoint (۲۳.۱)، اتصال پایگاه‌داده/API خارجی (۳۱)، صف پردازش خروجی حجیم با مانیتورینگ سلامت (۲۸ و ۳۰.۲)، کارت مقایسه‌ای و نقشه جغرافیایی، جدول کیفیت داده و اجزای متنی/تصویری و شناسنامه شاخص (تکمیل کامل ۱۹.۲)، قابلیت‌های هوشمند و هوش مصنوعی (۲۵)، توابع آماری پیشرفته (۱۳.۲)، تبدیل‌های Unpivot/Pivot (۱۰.۲)، موتور تحلیل متوسط DuckDB/Parquet (۲۷.۲) و داشبورد هوشمند خودکار پس از بارگذاری پیاده‌سازی و با آزمون e2e چهل‌وچهارفازی تأیید شده‌اند.

## تجربه کاربری و راهنمای درون‌برنامه‌ای (بازطراحی فاز سیزدهم)

- **سایدبار راست‌به‌چپ گروه‌بندی‌شده** به‌جای نوار تب‌های درهم‌ریخته: «مسیر ساخت گزارش» با ۶ گام شماره‌دار (فایل‌ها ← ستون‌ها ← پروفایل ← پاک‌سازی ← مدل ← گزارش‌ساز) به‌همراه گروه‌های تحلیل و هوشمند، ساختار و منابع، پایش و عملیات و سامانه؛ آیتم‌های نیازمند پیش‌نیاز با آیکون قفل و توضیح علت نمایش داده می‌شوند.
- **تولتیپ راهنما روی اقدام‌ها**: همه آیتم‌های ناوبری، دکمه‌های اجرا/ذخیره/انتشار/خروجی گزارش‌ساز و بارگذاری فایل توضیح کوتاه کاربردی دارند.
- **راهنما در هر بخش**: کارت جمع‌شو «راهنمای این بخش — گام به گام» با نکته طلایی در هر ۱۷ تب، تور راهنمای تعاملی هشت‌گامی با دکمه پرش (دکمه «راهنما» در سربرگ؛ باز شدن خودکار در نخستین ورود) و نوار «مسیر ساخت گزارش در ۵ گام» در گزارش‌ساز.
- **هویت بصری زمردی**: پالت سازمانی با حالت روشن/تاریک، انیمیشن ورود محتوا، کارت‌های با ابهت و منوی کشوی موبایل.

## تجمیع چند فایل هم‌فرم و قالب‌های هوشمند (فاز پانزدهم)

- **بازیابی گذرواژه**: اگر گذرواژه فراموش شده باشد، مدیر سامانه می‌تواند از بخش «مدیریت کاربران» آن را بازنشانی کند؛ اگر دسترسی مدیر قطع شده باشد، روی سرور برنامه این دستور اجرا می‌شود:

```powershell
.\scripts\reset-password.ps1                       # بازنشانی گذرواژه مدیر نخست به Admin@1404
.\scripts\reset-password.ps1 -List                 # فهرست کاربران
.\scripts\reset-password.ps1 -Username admin -Password "MyNewPass123"
.\scripts\reset-password.ps1 -Create -Username admin -Name "نام شما" -Password "MyNewPass123"
```

(نسخه لینوکس/مک: `node scripts/reset-password.cjs [username] [newpass]` — نشست‌های همان کاربر خودکار باطل می‌شوند و راهنمای کوتاه نیز در صفحه ورود قرار دارد.)

- **تجمیع چند فایل هم‌فرم**: در «فایل‌ها و مجموعه‌داده» فایل‌ها تیک می‌خورند و دکمه «تجمیع و ساخت داشبورد» ساختار همه فایل‌ها را مقایسه می‌کند (dryRun)؛ اگر هم‌فرم باشند، رکوردها با ستون «فایل مبدأ» در یک مجموعه‌داده یکپارچه می‌شوند و داشبورد و گزارش هوشمند روی کل داده ساخته می‌شود (مثلاً فیش حقوقی دو ماه در یک تحلیل).
- **قالب‌های هوشمند (تشخیص خودکار)**: پس از بارگذاری یا تجمیع، ساختار فایل با واژگان فارسی/عربی بررسی می‌شود و اگر «فیش حقوقی»، «صورت مالی (سود و زیان)» یا «داده سود» باشد، تب «تحلیل تخصصی» به‌صورت خودکار باز می‌شود:
  - **فیش حقوقی**: تعداد کارکنان، جمع خالص/ناخالص، جمع و نسبت کسورات، میانگین هر نفر، روند دوره‌ای، ترکیب مؤلفه‌های دریافتی (پایه/اضافه‌کاری/مزایا)، تفکیک واحد سازمانی، ۱۰ دریافتی برتر و بینش‌های فارسی (تمرکز پرداخت، دریافتی دور از میانگین).
  - **صورت مالی**: بازسازی صورت سود و زیان در دو حالت طولی (ستون شرح/مبلغ) و عرضی (هر قلم یک ستون)، تحلیل عمودی (درصد از فروش)، حاشیه سود ناخالص/عملیاتی/خالص، روند فروش و فشار بر حاشیه، برآورد اقلام محاسبه‌شده.
  - **سود**: محاسبه خودکار سود از درآمد و هزینه در هر رکورد، سود و حاشیه به تفکیک محصول/مشتری، اقلام زیان‌ده، تمرکز سود و روند دوره‌ای.
  - هر سه قالب شامل «گزارش هوشمند» متنی فارسی با دکمه چاپ/PDF هستند و تحلیل تخصصی از دکمه «مخفی کردن» یا «ویرایش داشبورد» قابل کنترل است (hiddenTemplates در چیدمان ذخیره می‌شود).
- **نمونه‌های آماده برای آزمون**: فایل‌های «نمونه-فیش-حقوقی-مهر/آبان»، «نمونه-صورت-مالی» و «نمونه-سود-محصولات» از همان صفحه بارگذاری قابل دریافت‌اند و سناریوی کامل (تجمیع دو فیش ← داشبورد تخصصی) را پوشش می‌دهند.

## گزارش هوشمند، ذخیره و انتشار (فاز شانزدهم)

- **گزارش هوشمند مستقل برای «هر» اکسل**: در تب «داشبورد هوشمند»، تب «گزارش چاپی» سند کامل گزارش (سربرگ، کارت‌های شاخص با روند، نمودار روند دوره‌ای با جدول مقایسه، تفکیک و دونات سهم، بینش‌های خودکار و جدول خلاصه) را برای هر مجموعه‌داده و بدون هیچ پیکربندی می‌سازد — دقیقاً در سبک نمونه‌های HTML ارسالی. دکمه‌های «چاپ / PDF» (قالب A4 فارسی) و «دانلود HTML» (فایل خودبسنده قابل باز شدن در هر مرورگر) در دسترس است.
- **ذخیره به‌عنوان گزارش**: دکمه «ذخیره به‌عنوان گزارش» داشبورد هوشمند را با چیدمان فعلی در پروژه ذخیره می‌کند؛ ذخیره دوباره نسخه جدید ثبت می‌کند (نسخه‌بندی بخش ۲۶.۱) و تاریخچه حفظ می‌شود. گزینه «ارسال برای تأیید» گردش کار را آغاز می‌کند و مدیر سامانه می‌تواند «انتشار فوری» را با ثبت کامل زنجیره تأیید (ارسال ← تأیید ← انتشار) انتخاب کند.
- **لینک عمومی اشتراک (انتشار)**: پس از انتشار گزارش، دکمه «صدور لینک عمومی» یک نشانی `/share/<توکن>` می‌سازد که بدون ورود قابل مشاهده است؛ لغو انتشار یا لغو اشتراک، لینک را بلافاصله غیرفعال می‌کند. ستون‌های محرمانه در صفحه عمومی با نقش مشاهده‌کننده ماسک می‌شوند و صفحه برای موتورهای جست‌وجو noindex است. گزارش‌های طراح‌گزارش (جدول/نمودار) نیز پس از انتشار همین لینک را می‌گیرند.
- **شروع سریع گزارش‌ساز**: در «گزارش‌ساز (گام ۶)» نوار «شروع سریع» با یک کلیک پیکربندی را انجام می‌دهد: «جدول خلاصه»، «نمودار تفکیکی»، «روند زمانی» (نیازمند ستون تاریخ) و «کارت شاخص» — بر اساس ستون‌های مجموعه‌داده و بلافاصله اجرا می‌شود تا ساخت گزارش دستی سخت نباشد.
- **آزمون**: `BASE=http://localhost:3000 bash scripts/e2e_phase16.sh` — ۳۳ آزمون (گزارش HTML، ذخیره/نسخه‌بندی، انتشار فوری، لینک عمومی برای هر دو نوع گزارش، رد اشتراک پیش‌نویس، لغو اشتراک).

## پایپ‌لاین خودکار پس از بارگذاری (فاز هفدهم)

- **بارگذاری = داشبورد؛ بدون هیچ کلیک اضافه**: پیش از این، پس از بارگذاری فایل کاربر باید خودش شیت را انتخاب و «ایجاد مجموعه‌داده» را می‌زد — اکنون بلافاصله پس از بارگذاری، سامانه به‌طور خودکار بهترین برگه را انتخاب (امتیازدهی بر اساس ناحیه داده، اخطارها و سلول‌های ادغام‌شده)، مجموعه‌داده می‌سازد و مستقیماً «داشبورد هوشمند» را باز می‌کند. این همان حلقه گمشده‌ای بود که کاربر را پس از بارگذاری متوقف می‌کرد.
- **تجمیع خودکار چند فایل هم‌فرم**: اگر در یک بارگذاری چند فایل انتخاب شود، ساختار فایل‌ها به‌طور خودکار مقایسه می‌شود؛ در صورت هم‌فرم بودن، همه در یک مجموعه‌داده یکپارچه تجمیع (ستون «فایل مبدأ») و داشبورد و گزارش هوشمند ساخته می‌شود — مثلاً دو فیش حقوقی مهر و آبان را با هم رها کنید تا داشبورد تخصصی فیش حقوقی ظاهر شود. اگر ساختار یکسان نباشد، از بزرگ‌ترین فایل داشبورد ساخته و راهنمای تجمیع دستی نمایش داده می‌شود.
- **نوار پیشرفت مراحل**: در حین ساخت خودکار، مراحل «شناسایی ساختار ← ساخت مجموعه‌داده ← تجمیع فایل‌های هم‌فرم ← تحلیل و داشبورد هوشمند» با وضعیت زنده نمایش داده می‌شود تا کاربر همیشه بداند چه اتفاقی در جریان است.
- **دکمه «ساخت خودکار داشبورد» برای فایل‌های قبلی**: کنار هر فایل بارگذاری‌شده دکمه‌ای افزوده شد که همان پایپ‌لاین خودکار را بدون بارگذاری مجدد اجرا می‌کند (برای فایل‌هایی که پیش از این نسخه بارگذاری شده‌اند)؛ پیکربندی دستی شیت‌ها هم مانند قبل در دسترس است.
- **آزمون مرورگر**: بارگذاری تک‌فایل فروش ← هدایت خودکار به داشبورد با ۴۰ رکورد؛ بارگذاری هم‌زمان دو فیش حقوقی ← «تجمیع خودکار 2 فایل» با ۲۴ رکورد و تشخیص خودکار قالب تخصصی فیش حقوقی (۱۰۰٪) — بدون خطای کنسول.

## راه‌اندازی و ورود

```bash
bun install && npx prisma db push && bun run dev
```

نخستین کاربری که ثبت‌نام می‌کند، **مدیر سامانه** می‌شود (راه‌اندازی اولیه — بخش ۲۹ سند). پس از ورود، از تب «مدیریت» کاربران و نقش‌ها و از تب «فرهنگ داده» شاخص‌های سازمانی را تعریف کنید.

> توصیه: با یک فایل واقعی سازمان شروع کنید تا تشخیص ساختار (سطر سرستون، دامنه داده، واحد پول) متناسب با داده‌های شما تنظیم شود (بخش ۳۰.۱ و ۳۶).
